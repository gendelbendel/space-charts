# UI

- Layout tiers live in `v2/pages/index.html`: **phone** (<600px: docked controls, tabbed visuals, stacked when the `viz` container is ≥430px tall), **tablet** (600–899px and >520px tall), **short landscape** (≤520px tall, ≥600px wide), **desktop** (≥900px and >520px tall; 900–1199px stacks the stats full width). Shared components go in `base.css`. (Why: `docs/WHY.md#everything-the-slider-changes-stays-on-one-screen`)
- In the tabbed tiers only the Numbers tab scrolls; the chart and the color map shrink to fit (`flex: 1 1 0`, the legend hides in the shortest `viz`), and `check:layout` fails a panel that scrolls. The color map's `viewBox` follows its box (`initCie`): wide boxes crop the greens at the top so the blackbody curve fills the space, so the svg's size must come from CSS, never from its `viewBox`.
- Never rebuild the HTML of something the reader may have scrolled: Safari moves its scroll position (the Numbers tab jumped on every slider step). `renderObjects` updates the prerendered cards in place; `renderPipelines` restores the tab's `scrollTop`. Below 900px wide, and in short landscape, each object category is a row that swipes sideways.
- Nothing may change size when a mode, model or temperature changes: give changing text a fixed height, a reserved line count, or `nowrap` with ellipsis. Text inputs ignore line-height; give them an explicit height in `em`. Verify with `npm run check:layout`: it builds, then runs `v2/tools/layout-stability.js` (movement, overlap, containment) in Playwright at 12 sizes across the four tiers, and adds first-screen and desktop column-balance checks (`--sizes 375x667,1440x900` to narrow it, `--browser webkit` after `npx playwright install webkit`). To run the stability check by hand in a browser: `cp v2/tools/layout-stability.js build/__layout-check.js`, then in the page run `eval(await (await fetch('/__layout-check.js')).text())`. `build/` is never committed. (Why: `docs/WHY.md#nothing-moves-when-modes-change`)
- The big temperature is also the text box (`#num` inside `#tempBig`): it shows "5,772", edits as "5772", and applies on Enter or blur (Escape and junk revert). Its type size is fixed per tier and sized for 1,000,000 K; never scale type by content length. Its width comes from the hidden `.temp-measure` mirror span. The class badge leads the verdict line, not the number's row.
- A change that should look identical (refactors, moving code, prerendering) is proven with `npm run snapshot:save` on the commit before and `npm run snapshot:compare` after. When adding a control or view, add a state for it to `STATES` in `v2/tools/snapshot.mjs`. Baselines live in `v2/.snapshots/` (gitignored), outside `build/` because `build:v2` wipes it.
- Desktop column balance: `--stage-h` and `--viz-h` scale together so the left column and the chart column end together. `check:layout` fails if `.b-left` and `.stats` end more than 20 px apart at 1024×768, 1280×720 or 1440×900.
- The slider's mapping is `SLIDER_KNOTS` in `slider-scale.js`, chosen by the owner, and a test pins how much of the bar each range gets. (Why: `docs/WHY.md#the-slider-favors-the-temperatures-where-color-changes`)
- Anything drawn along a slider uses `alongSlider()` and the scale's `toFraction`, never a raw percentage of the row. Labels go through `createSliderMarks`, which hides colliding labels by priority. (Why: `docs/WHY.md#slider-marks-follow-the-thumb`)
- One-way flow: `state` (in `state.js`) → `render()` → DOM. Each UI module (`controls.js`, `readout.js`, `stage.js`, `chart.js`, `cie-diagram.js`, `pipelines.js`, `objects-list.js`, `orion.js`, `faq.js`, `share.js`, `play.js`, `keys.js`) owns its elements and listeners and exports a render function; `app.js` calls them in order. Modules change state only through `update(patch)` or `setTemperature(T)`, which re-render. Never import `app.js` from a module. `format.js` is pure (no DOM) so the build can use it. Bundled as an IIFE, so nothing is global; in the browser console, drive the page through the DOM (set `#slider.value` and dispatch `input`), not by calling its functions.
- The first screen is prerendered: `build.mjs` fills `{{name}}` slots in the partials from `v2/src/prerender.js`, which calls the same builders the page uses. A module the build imports must not touch the page when it loads: put listeners and lookups in an `init…()` called from `app.js`. Anything new on the first screen that the script fills needs a slot (or a CSS-reserved size); `check:layout` fails if a block moves when the script runs. (Why: `docs/WHY.md#the-first-screen-is-prerendered-from-the-same-builders`)
- Anything that moves the temperature by code (Play, the tour) uses `animateTo` from `animate.js`. While it runs, `state.animating` is true and `render()` skips the pipelines and objects HTML (measured: that holds 60 fps at 4× CPU throttle; full renders don't). Input goes through `setTemperature()`, which clears the flag and so stops the animation; don't call `update({ T })` for user input.
- Keyboard shortcuts live in `keys.js` and are listed in `partials/keys.html`; keep the two in step. They're ignored in text fields and with Ctrl, Alt or Cmd.
- The page reads `?t=` (and v1's `?temp=`), `model`, `light` and `compare`, and writes back via `history.replaceState` (wrapped in try/catch for `file://` previews). Keep old links working.
- Dark only. Colors come from the `:root` tokens in `base.css`. No raw colors in components, except star and spectrum colors computed by the physics.
- Partials are expanded at build time. An element ID used by a module must appear exactly once per page.
- The game (`/play/`, `pages/play/index.html`) is its own page with its own tiers: one column, except short landscape (star left, round right). Its disc size comes from the viewport height so a whole round fits on the first screen from 320×568 up. Rules live in `game.js` (pure, tested in `test/game.test.js`); the UI in `game-page.js` reuses `stage.js`'s `discPaint`, the slider marks and `share.js`. The game's slider track stays neutral grey: a colored track would give the answer away. `check:layout` and the snapshots cover only the main page.
- FAQ answers stay collapsed until tapped, including after a search.
- Never play sound while testing (owner's global rule). The page has no audio today; keep it that way unless asked.
